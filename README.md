# clcom

基于 Python + PySide6 的串口调试和 Lua 自动化工具，适合串口收发、指令管理、协议调试、OTA、字库下载和自动化测试。当前默认 GUI 入口为 PySide6，旧版 tkinter 入口、旧 Tk UI、旧 controller 和兼容代理已完成清理。

## v3.04 更新摘要

- 升级版本号到 `v3.04`。
- AI 页接入协议日志分析 agent 能力，聊天分析会自动结合串口状态、日志上下文、协议知识和历史经验。
- 迁移历史协议知识库到当前软件内置知识库，发布包只携带 `protocol_agent/knowledge` 中的示例/说明知识片段，不包含本机导入的具体产品协议资料。
- 新增 RAG 检索服务，支持 BM25 风格评分和中英文关键词扩展，协议解释会带 `[P1]`、`[P2]` 证据引用。
- 协议文档学习能力增强，支持多文件导入、文件夹递归导入以及 `txt`、`md`、`csv`、`json`、`yaml`、`html`、`docx`、`xlsx`、`xls` 等类型。
- AI 学习记录补强证据、适用范围、置信度和用户确认规则，候选经验必须确认后才会作为已确认经验使用。
- AI 页更多菜单中的历史知识导入入口去掉具体外部软件名，界面文案更通用。
- 发布脚本补充 `protocol_agent/knowledge` 打包过滤，避免发布版缺少默认示例知识库，同时不打包本地 `learning.json` 和当前本机导入的具体协议知识。
- AI 远程请求统一使用准备后的上下文和请求指纹，Chat、Responses、Agent 与分块分析的实际发送内容保持一致。
- 增加请求 token 隔离，旧请求的结果、统计、缓存状态、进度和流式输出不会覆盖新请求。
- 完善远程请求与 Agent 的协作式取消生命周期跟踪，支持等待后台请求和模型/工具调用真正退出。
- 大日志分块汇总保留原始行号证据，并明确标记分块缺失或内容截断，避免把不完整结果当作完整分析。
- 日志分析最终报告增加证据、行号、原因、建议和置信度校验；报告不完整时不会自动生成候选经验。
- 学习知识文档与学习记录使用统一 `learning_id` 原子关联，任一保存失败会恢复已有文件和索引。
- 修复本地分析对 RX-only 日志的误判，增加 TX/RX 关联、超时、CRC、首个错误和下一步建议，并限制重复行号输出。
- 修复日志刷新滚动位置：默认跟随最新日志，用户手动上移后刷新保持当前位置；文本和表格模式均适用。
- 兼容部分 OpenAI-compatible 服务返回普通文本的 Agent 最终回答，不再误判为 JSON 决策协议失败；不完整报告仍不会生成候选经验。
- 修复设置页 AI 本地缓存相关文案乱码。

## v3.03 更新摘要

- 串口标签页标题继续显示标签名和端口号，标签页新增可点击关闭入口；深色主题下关闭 `X` 改为高对比自定义按钮，避免看不清。
- 浅色、深色和护眼主题改为使用应用级调色板切换颜色，不再用全局 QSS 改变按钮、输入框、分组框和标签页盒模型，主界面布局保持和默认主题一致。
- 界面语言设置新增简体中文/English 切换，主要页面、动态列表、弹窗和模板说明继续补齐中英文文案。
- Lua 编辑器左侧新增行号栏，语法高亮区分关键字、函数、变量、字符串、数字和注释；Lua 日志双击可跳转到对应脚本行。
- Lua API 速查入口恢复为图标按钮弹窗，自动补全改为编辑器内候选列表，并避免 `Ctrl+Space` 与中英文输入法切换冲突。
- 日志过滤支持多个关键字使用不同颜色高亮，主日志界面和过滤结果窗口保持一致；过滤弹窗双击结果会跳转并高亮主日志对应条目，不关闭过滤窗口。
- 设置页继续补齐串口默认参数、日志显示、Lua、AI、自动更新、异常恢复和配置维护项，并保存用户上次选择的文件夹、串口参数和界面布局。
- 独立串口窗口还原、过滤、日志跳转和发送队列跳转继续和主界面行为对齐，减少多串口并行时的状态串扰。
- `update.json` 发布说明改为 UTF-8 正常中文，避免 Gitee/GitHub Release 更新说明出现乱码。

## v3.02 更新摘要

- PySide6 版本进入基础功能收口阶段，默认 `python main.py` / `python pyside_main.py` 启动新版界面；`main.py --tk` 旧版入口已移除，旧 tkinter 代码、旧 controller 兼容层和旧 UI 目录已完成清理。
- PySide 串口标签页标题现在会显示当前端口号，例如 `串口1 COM3`，切换端口、恢复标签配置或从独立窗口还原后会同步刷新，便于多串口并行时快速识别。
- 串口端口下拉框在展开前会自动刷新当前系统端口列表，减少插拔串口后还需要手动点击“刷新”的操作。
- 串口端口下拉框会显示端口简要提示，包含描述、厂商和序列号等基础信息；同一端口已被其他串口标签打开时会在当前标签提示占用，并阻止重复打开。
- 串口主界面端口提示不再显示 VID/PID；VID、PID、序列号、厂商和硬件ID 统一移动到串口诊断页和诊断导出内容中，避免主界面信息过密。

- 串口诊断导出增强为现场诊断包入口，会包含所有串口会话摘要、可用端口详情、脱敏后的当前设置、发送队列摘要和最近日志片段。

- 串口诊断页新增“对象”选择，默认汇总全部主界面标签和独立窗口串口，也可切换到单个串口查看 VID/PID、打开状态、TX/RX 统计、重连次数和最近异常。

## 主要功能

- 串口打开、关闭、参数配置、拔插检测和自动重连。
- 左侧主收发区支持多个串口标签页，每个标签页拥有独立端口、发送框、显示模式、收发日志、统计和日志文件；Lua 脚本、指令列表和小工具发送默认使用当前选中的串口标签页，Lua 也可通过 `serial.send_to()` / `serial.send_hex_to()` 指定标签名或端口发送。
- 串口写入失败、重连失败、Lua 回调异常和日志文件写入失败会进入统一异常状态，恢复动作可在设置页统一配置，底部状态栏和串口诊断页会显示异常来源、时间、次数和恢复动作。
- 支持文本、HEX、HEX+文本显示。
- 文本显示模式会自动检测 RX 数据：纯文本直接显示文本，明显二进制显示 HEX，混合数据同时显示 HEX 和可读文本，避免控制字节或乱码导致原始数据缺失。
- RX 显示支持按换行、原始、超时合并、AA55 帧头和自定义模板模式；默认按回车/换行分帧，可按设备协议习惯把连续接收数据聚合成更接近协议帧的日志。按换行模式遇到明显二进制数据时会自动透传当前接收块，避免 OTA 响应被随机 `0D/0A` 字节拆分或延迟到后续 TX/Lua 日志之后写入。
- 收发日志支持 Text 虚拟窗口和主界面表格视图两种查看方式；文本视图使用独立行号边栏，行号紧贴日志区域左侧边界，便于和过滤结果、日志索引、Lua 日志、发送队列定位结果对应，同时复制日志正文时不会混入行号；表格视图按时间、类型、来源、等级、长度和内容分列显示，支持右键复制、解析和跳回文本上下文。多串口标签页和拖出的独立窗口会分别保存各自的过滤条件、过滤高亮、表格控件和日志视图状态。
- 收发日志按实际 TX/RX 事件时间记录和排序，RX 即使晚于 TX/Lua 进入 UI 队列，也会按事件时间插入到主日志正确位置；关闭软件或关闭串口前会写完剩余日志。
- 创建日志文件时会同步生成 `.idx` 轻量索引文件，记录分块行号、时间和文件偏移，为后续大日志快速跳转做准备。
- 日志显示区采用虚拟窗口，只渲染当前可见日志切片；高频 RX 或 Lua 日志暴增时 UI 会自动降频显示并在状态栏提示，文件日志仍按完整事件写入。
- 支持日志导入、主日志暂停/恢复显示、右键菜单、日志书签、搜索和按 TX/RX/Lua/系统/Lua等级分类过滤；常用过滤条件可保存为过滤模板，也会自动进入“最近过滤”下拉便于快速复用；结果以弹窗显示，双击结果可跳转到主日志位置查看上下文，并支持复制、导出和发送到协议解析。
- 发送队列页显示发送序号、时间、状态、字节数、耗时、来源和数据，支持过滤、导出和批量重发失败项。
- 底部状态栏显示 TX/RX 统计、RX 帧数、串口状态、最后 TX/RX 时间、重连次数和最后错误。
- 串口诊断页显示当前端口、端口存在性、真实可用状态、断线次数、重连次数、打开/重连耗时、启动自检结果、最近诊断事件和最后错误；导出诊断会包含所有串口会话摘要、可用端口详情、脱敏后的当前设置、发送队列摘要和最近日志片段。
- 指令列表支持分组、新增、搜索、重命名、删除、导入、导出、清空、自动保存、收藏置顶、最近发送和批量修改，并支持期望回复、超时、重试和备注。
- 发送流程编排器支持不用写 Lua 配置 `SEND`、`WAIT`、`SLEEP`、`LOG` 等步骤。
- Lua 编辑器支持语法高亮、自动缩进、`Ctrl+S` 保存、`Ctrl+Shift+Space`/`Alt+/` 代码补全。
- Lua API 速查使用图标入口，支持双击或点击插入接口模板，并记录最近使用的接口。
- 修复 PySide Lua 页 API 图标点击无响应的问题；PySide 冒烟测试已增加 Lua API 速查弹窗打开检查。
- Lua 运行监控显示运行时间、Lua TX 数、log 数、错误数、回调数、定时器数和队列积压；运行前会做高风险接口扫描和常见参数校验；运行结束会输出 Lua 运行报告；Lua UI 消息和 RX 回调均支持批处理，降低脚本高频收发时的界面卡顿。Lua 页支持运行报告导出和脚本模板库。
- AI 助手支持聊天式输入输出，自动收集串口状态、最近异常、最近日志、Lua 错误和协议模板作为上下文；配置 OpenAI 兼容接口后会优先使用远程 AI，失败时自动回退本地分析。
- 小工具默认包含 ASCII、CRC、协议解析、随机数、Modbus RTU；CRC 支持指定计算起始位置、CRC 插入位置、HEX 分隔符智能识别和处理后数据串口发送，协议解析支持自定义模板、字段表解析、导入导出、绑定串口并保存到本地。
- 右侧“关于”页提供版本信息、工具介绍、编写人员、免责声明、日志目录入口和远程更新检查。
- 首次启动会显示基础设置向导；配置文件损坏时会自动备份坏文件并使用默认配置恢复启动，设置页可查看并恢复配置备份。
- 主窗口默认加宽，右侧标签页区域拥有更宽的显示空间，便于查看指令列表、Lua 脚本、流程编排和小工具。
- `scripts/` 目录作为外置脚本目录发布，用户可直接修改和新增脚本，不会被打进 exe。

## 现场任务手册

### 我要升级 OTA

1. 在左侧串口标签页选择目标端口和波特率，确认底部状态为已打开。
2. 在右侧 `自动 / Lua` 打开 OTA 脚本，例如 `ET10_OTA.lua` 或 `ota_upgrade.lua`。
3. 运行前确认弹出的风险提示，OTA、文件访问和批量发送属于高风险操作。
4. 选择升级文件后开始执行，观察左侧 TX/RX 日志和 Lua 页运行报告。
5. 升级结束后点击 `打开日志` 或 `索引` 查看完整日志；如果怀疑丢日志，先导出诊断包再复现。

### 我要抓异常日志

1. 打开串口前确认左侧 `保存日志` 已勾选。
2. 根据设备输出选择 `文本显示`、`HEX显示` 或 `HEX+文本`；编码设置会同时影响文本显示、文本发送、Lua 文本发送和日志文件保存编码。
3. 复现问题时不要频繁清空日志，必要时点击 `暂停显示` 降低 UI 干扰，文件日志仍会继续写入。
4. 复现完成后关闭串口或关闭软件，程序会强制写完未落盘日志。
5. 使用 `打开日志` 查看日志文件，或用 `索引` 按行号/时间跳转大日志上下文。

### 我要解析一帧协议

1. 在主日志中选中包含 HEX 字节的 RX/TX 行。
2. 右键选择 `发送到协议解析`，或点击日志工具栏中的 `解析选中`。
3. 在 `工具 / 小工具 / 协议解析` 中选择模板；没有模板时先填写 header、长度字段、CRC 和字段表。
4. 需要一次解析多条数据时，将解析模式改为 `按帧头/长度` 或固定长度模式。
5. 调整字段表后保存模板，后续可绑定当前串口并用于自动解析。

### 我要用 Lua 自动测试

1. 在右侧 `自动 / Lua` 新建或打开脚本。
2. 使用 API 速查插入 `serial.send()`、`serial.send_hex()`、`serial.wait()`、`serial.assert_reply()` 或 `serial.assert_hex()`。
3. 如果要指定串口标签或端口，使用 `serial.send_to()` / `serial.send_hex_to()`。
4. 运行前查看风险提示；脚本执行中可在 Lua 页查看运行状态、错误详情和日志分析。
5. 执行结束后导出 Lua 运行报告，便于和串口日志一起定位问题。

### 出问题了如何导出诊断包

1. 进入右侧 `调试 / 诊断`。
2. 点击 `刷新` 查看当前端口状态、重连次数、最近错误和日志文件路径。
3. 点击 `导出诊断包`，软件会打包配置摘要、运行异常、诊断事件和最近日志上下文。
4. 多串口长期测试时点击 `导出测试报告`，生成 Markdown 记录表。
5. 发布前或现场复现后，可在命令行运行 `python tools/diagnostics/field_reliability_check.py --duration 10` 生成自动检查报告。

## 功能模块说明

### 主收发区

主收发区负责日常串口调试，包括端口选择、串口参数设置、手动发送、TX/RX 日志查看、日志过滤和协议解析入口。左侧日志区优先保证高频接收时界面可操作，日志数据先进入结构化事件和文件日志队列，再按虚拟窗口渲染到界面。

左侧收发区顶部的 `+` 可新增串口标签页，鼠标悬停会提示“新建串口标签页”；每个标签页可以选择不同端口并独立打开、接收、发送和保存日志。切换标签页不会停止其他已打开串口的接收线程，后台收到的数据会继续写入对应标签页的结构化日志和日志文件。当前版本中 Lua 脚本、指令列表发送、CRC 工具发送等主动发送入口默认使用当前选中的串口标签页。

串口标签页操作：

- 标签标题会显示状态、标签名和端口，例如 `[开] 主控MCU COM3`；未选中标签收到数据时会显示未读数量。
- 右键标签可重命名、复制当前配置新建、拖出为独立窗口、关闭当前标签、关闭其他标签或关闭已断开标签。
- 鼠标按住标签拖出主窗口区域后，会变成独立串口收发窗口；双击独立窗口或关闭独立窗口，会回到主窗口标签页。
- 新增标签会尽量自动选择一个未被其他标签使用的串口；如果没有空闲串口，则保留系统返回的可用端口。
- 软件关闭时会保存串口标签页名称、端口、波特率、显示模式、日志选项和发送选项；下次启动自动恢复标签页，但不会自动打开串口。

显示模式说明：

- `文本显示`：自动判断 RX 数据格式；纯文本显示文本，二进制显示 HEX，混合数据同时显示 HEX 和可读文本，保证原始字节可追溯。
- `HEX显示`：所有 RX 数据统一显示为十六进制字节。
- `HEX+文本`：先显示 HEX，再在数据整体可读时追加文本行，便于同时核对原始字节和文本含义。

RX 分帧说明：

主收发区已不再直接显示 RX 分帧设置，分帧策略统一放到“设置”页中配置，减少主界面常用收发区域的拥挤程度。配置后会立即影响后续 RX 日志显示、自动解析和文件日志记录。

- `原始`：按串口底层本次读到的数据块显示，延迟最低。
- `超时合并`：把短时间内连续收到的数据合并后显示，适合一帧被系统拆成多次回调的场景。
- `按换行`：默认模式，收到回车 `\r`、换行 `\n` 或 `\r\n` 后作为一条日志显示，适合 AT 指令、文本协议和行协议。
- `帧头AA55`：按 `AA 55 + 长度` 的简单帧格式尝试切帧，适合快速验证类似帧头协议；复杂协议建议使用小工具中的自定义协议模板。
- `自定义模板`：按用户配置的帧头、长度字段下标、长度字段字节数、总长修正、帧尾和最大帧长切帧。
- `间隔ms`：用于超时合并和未完整分帧数据的兜底刷新。

日志相关控件说明：

- `显示发送`：控制 TX 是否显示到主日志和当前文本日志文件。
- `保存日志`：控制当前串口标签页是否写入日志文件。
- `打开日志`：打开当前日志文件或日志目录。
- `导入日志`：把历史日志导入主显示区用于查看和过滤。
- `过滤类型` 与 `关键字`：按 TX、RX、Lua、系统等类型以及多个关键字异步过滤。
- `解析选中`：把选中的 RX/TX HEX 数据送到协议解析小工具。
- `暂停显示`：暂停主日志界面刷新，但不暂停串口收发和文件日志写入。
- `表格`：在主日志区域内切换文本视图和表格视图，不额外弹窗；表格右键可复制、解析或跳回文本上下文。
- `RX自动解析`：收到可提取 HEX 的 RX 日志时自动送入协议解析页，默认关闭，避免高频接收时频繁切换右侧工具。

### 串口管理

串口管理包含端口枚举、打开关闭、运行中参数应用、TX payload 格式化、RX 接收循环、RX UI 队列调度、物理拔插检测、后台自动重连、统一写入和发送失败后一次重连重试。工具会区分 `pyserial.is_open` 与真实端口可用状态，解决设备拔出后对象仍显示打开但实际不可通信的问题。串口写入失败、Lua 回调异常和日志文件写入失败会进入统一异常状态，并记录到最近异常列表。串口诊断页会汇总最近诊断事件和发送失败原因统计，便于定位断开、重连和写入失败。

### 指令列表

指令列表用于维护常用发送命令。每条指令支持名称、数据、HEX 类型、期望回复、期望回复类型、超时时间、重试次数和备注。指令按组管理，支持新建组、重命名、删除、导入、导出、清空、自动保存和批量操作。导入前会预览识别到的组和指令数量，确认后才写入。列表采用虚拟渲染，适合上百或上千条指令的场景。新版指令文件带 `config_version`、`current_group` 和 `groups` 字段，读取时仍兼容旧版列表和分组格式。

### 发送流程编排

流程编排器用于不写 Lua 的简单自动化收发。它支持发送指令列表项、发送 HEX、发送文本、等待文本或 HEX 回复、延时、变量和条件判断。适合固定步骤的协议验证、生产测试前置检查和简单查询流程。当前流程可点击“保存模板”写入本地 `flow_templates.json`，保存后会出现在“示例”窗口中，方便复用。

### Lua 自动化

Lua 页提供脚本编辑、保存、补全、API 速查、运行、停止、日志等级控制、日志限流、进度显示、接收回调和定时器能力。Lua 脚本可以调用串口收发、等待回复、读取文件、CRC 计算、发送指令列表项和显示进度。运行前会扫描高风险接口，涉及文件访问、批量发送、OTA 或关闭日志时会弹窗确认，弹框内可勾选“不再提示”；同时会检查 `serial.send_hex()`、`protocol.from_hex()` 等常见 HEX 参数格式，以及负数超时/长度参数。脚本结束或进入监听状态时，会输出本次耗时、TX/RX 增量、Lua TX 次数、日志数、错误数和风险接口数量。

### 小工具

右侧小工具直接嵌入主界面，内部使用标签页切换各个工具，不再使用按钮切换。默认顺序为 ASCII、CRC、协议解析、随机数、Modbus。ASCII 支持自动转换；协议解析支持自定义模板、字段解析、校验配置、批量解析、模板保存、另存模板、导入、导出和绑定当前串口。协议模板会保存解析模式、固定长度和 CRC 校验参数，切换模板时会同步恢复。

### 设置页

设置页集中放置界面和运行策略配置：

- 设置页右侧提供纵向滚动条，窗口高度不足时可拖动滑块或使用鼠标滚轮查看全部设置项。
- 修改设置后，点击“应用到当前串口”“应用到全部串口”或关闭软件，都会保存当前设置；下次启动会优先恢复上次保存的设置和串口标签配置。
- 串口默认参数入口，包括默认波特率、数据位、校验位、停止位和文本/日志编码。
- 串口会话默认行为，包括默认显示模式、是否显示 TX、是否自动解析 RX、是否默认 HEX 发送、是否默认追加 CRLF、打开串口后是否自动写入日志。
- 日志显示字号、行高和主题，可统一调整主日志文本视图和表格视图中的日志文字大小、表格行高和配色。
- 会话配置保存和管理，可保存串口参数、显示模式、RX 分帧、日志路径和协议模板。
- 配置备份查看和恢复。
- 日志策略，包括文件排序延迟。
- 日志 UI 压力保护，包括降频阈值和状态栏提示开关；该策略只影响界面刷新频率，不影响日志文件完整写入。
- RX 分帧策略和自定义模板入口。
- 异常恢复策略，包括串口写失败、重连失败、Lua 回调异常和日志写失败，可配置为静默重试、提示用户、暂停脚本或提示导出诊断包。
- Lua 日志最低等级和每秒最大 Lua log 条数设置；默认不限制，避免 OTA 或高频脚本日志被误折叠。
- Lua 运行风险提示开关，可重新开启或关闭运行前风险确认弹框。
- Lua RX 回调批处理参数，用于高频接收场景降低脚本回调压力。
- 首次启动向导开关。
- AI 助手接口地址、模型、API Key、超时和发送前脱敏开关；发布包默认不会携带本地 API Key。
- 远程更新使用 GitHub Release 中的内置清单地址，普通设置页不再显示清单地址输入框，避免用户误改后无法检查更新。
- 界面布局相关设置。
- 日志字体大小。
- 浅色/深色日志区域主题。
- 日志导出脱敏开关，可隐藏 MAC、SN 和本地路径。
- 文件保存路径记录。
- 左侧可新增串口标签页，用于在同一个窗口中进行多串口多会话调试，标签也可拖出为独立窗口查看。

### 串口诊断

串口诊断页用于排查端口异常、断线重连和性能问题，显示端口存在性、串口对象状态、工具内部状态、TX/RX 统计、打开失败次数、断线次数、重连次数、耗时和最后异常。
诊断页还会显示“现场可靠性”摘要，包括文件日志待写数量、UI 显示队列积压、是否处于 UI 降频显示、重连恢复动作、Lua 当前行和回调数量，用于排查 OTA 高频日志、关闭前日志落盘、串口拔插和脚本异常恢复。

### 关于页面

关于页显示工具介绍、版本号、发布日期、编写人员、免责声明、日志目录入口和“检查更新”入口，方便发布给用户后查看使用范围、风险提示和远程版本状态。

### 远程更新

“关于”页提供“检查更新”。工具会从内置更新清单读取远程版本、发布包名称、SHA256 和更新说明，并和本地 `version.json` 或内置版本号进行比较。如果发现远程版本号更高，或同版本存在更新的发布包，会弹窗展示更新内容，并提供“打开发行版页面”和“下载并更新”。如果当前已经是最新版本但远程清单仍提供发布包，手动检查窗口会显示“重新下载并更新”，便于重新拉取同版本替换包。

软件启动时默认会在后台自动检查更新，设置页“AI 与远程更新”分组可关闭“启动时自动检查更新”，检查周期可选“每次启动 / 每天一次 / 每周一次 / 每月一次”，默认每天一次。启动自动检查失败时不弹错误框，只在关于页更新状态和主窗口状态栏提示；发现新版本时会弹出轻量提示，可选择打开发行版页面、下载更新或稍后处理。

自动更新采用最小替换策略：下载 release zip 后先校验 SHA256，只从更新包中提取并替换 `clcom.exe`、`update.json`、`version.json` 和 `README.md`，不会覆盖 `scripts/`、`commands.json`、`config.json`、日志目录和用户脚本。由于 Windows 不能可靠覆盖正在运行的 exe，点击“下载并更新”或“重新下载并更新”后，工具会直接显示下载进度条；下载、校验和准备完成后自动关闭当前软件，由后台临时脚本等待进程退出后完成替换并重新启动。

自动更新重启新版 exe 前会重置 PyInstaller onefile 运行环境，并清理 `_PYI_APPLICATION_HOME_DIR`、`_MEIPASS2` 等临时环境变量，避免新版程序误用旧 `_MEI` 临时目录后提示找不到 `python310.dll`。

远程更新清单位于 GitHub Release 的 `update.json` 附件中，同时会复制到发布目录。每次发布新版 zip 后，需要同步更新其中的 `version`、`build_time`、`package_name`、`package_url`、`sha256` 和 `notes`。普通设置页不显示清单地址输入框，后续如需要切换到对象存储或自有静态地址，应由发布配置或内置常量统一控制。

源码运行或缺少 `clcom.exe` 的开发环境下，自动替换会被阻止，需要手动构建或手动更新。

## 常用操作说明

以下操作在界面中未必都有完整文字提示，使用时可按本节说明操作。

### 串口和手动发送

- 展开端口下拉框时会自动刷新当前系统串口列表，也可以点击“刷新”手动刷新。
- 端口下拉框会通过提示信息显示 USB 串口描述、厂商、VID/PID 和序列号等详情；如果其他串口标签已经打开同一端口，当前标签会显示占用提示并禁止重复打开。
- 每个串口标签页都有独立端口下拉框、波特率、发送输入框、日志显示和统计；串口已打开时，切换端口会自动关闭当前标签页旧端口并打开新端口。
- 右键串口标签可重命名、复制配置新建、拖出独立窗口或批量关闭标签；拖出的窗口双击后会回到主窗口标签页。
- 串口已打开时，修改波特率并回车、失焦或从下拉框选择后会立即应用到当前串口。
- “设置”中的编码、校验位、数据位、停止位和自动重连开关点击“确定”后保存；串口已打开时会立即应用串口参数。
- 自动重连在后台静默进行，不会在收发日志区反复打印重试日志；重连状态可从底部状态栏和“串口诊断”页查看。
- 发送输入框按 `Enter` 等同于点击“发送”。
- 勾选 `HEX` 时，发送框按十六进制解析，允许空格和 `_` 分隔；未勾选时按当前编码发送文本。
- 勾选 `+CRLF` 时，会在本次发送数据后追加 `\r\n`。
- 手动发送、指令列表发送和 Lua 发送在串口未打开时会尝试自动打开串口；打开失败或写入失败会弹窗提示。

### 收发日志

- “显示发送”关闭后，TX 日志不会显示到主日志区，也不会写入当前显示日志文件；发送队列和底部 TX 统计仍会更新。
- 主日志区使用虚拟列表，只渲染当前可见附近的日志；滚轮或滚动条滚动时会按位置重新渲染对应日志切片。
- 主日志区提供横向滚动条，长行日志可用底部滑块左右拖动查看。
- 主日志文本视图和表格视图都会显示统一行号；过滤结果弹窗也显示相同行号，方便在主日志和过滤结果之间定位。
- 点击“暂停显示”只暂停主日志区刷新，不暂停串口收发、结构化日志记录和文件日志写入；再次点击“恢复显示”会重绘最近保留日志。
- 主日志中选中一行或多行 RX/TX HEX 数据后，点击“解析选中”会把可解析的 HEX 字节载入右侧“小工具/协议解析”页。
- 主日志区支持右键菜单，可复制选中/当前行、复制 HEX、复制为 Lua 发送语句、加入指令列表、添加/查看日志书签、发送到协议解析、发送到 AI 助手，或把选中文本直接作为过滤关键字。
- 日志过滤关键字输入框按 `Enter` 等同于点击“应用”。
- 多个过滤关键字可用英文逗号、英文分号、中文逗号或中文分号分隔；空格会作为关键字内容参与匹配，任意一个关键字匹配就会出现在过滤结果中。
- 每次应用非空过滤条件后，软件会把过滤类型和关键字记录到“最近过滤”下拉；选择下拉项会恢复该过滤条件并立即检索。
- “保存过滤”会把当前过滤类型和关键字保存为模板；点击“模板”可选择、应用或删除常用过滤模板，例如只看错误、只看 OTA、只看某个命令字。
- 日志过滤结果弹窗为非模态窗口，打开后仍可继续操作主界面、串口标签页和其他工具页。
- 日志过滤结果弹窗中，双击结果行或按 `Enter` 会跳转并高亮主日志对应位置，不会关闭过滤结果窗口，也不会影响串口打开状态；如果该日志已超出主界面保留范围，需要通过日志文件查看上下文。
- 在日志文本视图或表格视图中按 `Ctrl+F` 会直接聚焦当前串口标签的过滤输入框并选中原关键字；输入后按 `Enter` 会应用过滤。
- 过滤结果弹窗支持“复制选中”“复制全部”“导出结果”；选中包含 HEX 字节的 RX/TX 行后可点击“发送解析”载入协议解析页。
- 如需过滤历史日志，先点击“导入日志”载入文件，再使用主日志过滤条件进行检索；这样过滤路径与当前日志保持一致。
- 日志书签会保存日志时间、类型、分类、备注和文本；书签窗口可编辑分类/备注，如果对应日志仍在内存窗口中，可双击跳转。

### 指令列表

- 工具栏按钮使用图标显示，鼠标悬停图标会显示功能名称。
- 指令列表采用表格化虚拟渲染，只创建当前可见行控件；上百/上千条指令时切换组、搜索和滚动更平稳。
- 搜索框可按指令名称、数据、期望回复和备注筛选当前组；输入关键字后按 `Enter` 或点击“搜索”执行，多个关键字可用空格、逗号或分号分隔，任意一个命中即显示。
- 指令数据输入框编辑后会防抖自动保存；按 `Enter` 或输入框失焦时会立即保存。
- 指令列包含序号、数据、类型和操作；发送按钮直接显示指令名称，鼠标悬停可查看完整名称。
- 在指令行上右键可选择“收藏/取消收藏”；收藏指令会置顶显示。工具栏“收藏”可只看收藏项，在收藏列表中右键选择“删除收藏”即可从收藏列表移除。“最近”可查看最近发送记录并双击重发。
- 指令行右键还支持复制数据、复制为 Lua 发送语句、加入流程编排；最近发送列表中右键可把历史发送过的指令加入收藏或取消收藏。
- 左键点击指令发送按钮会发送该条指令；如果设置了期望回复、超时和重试，会按配置等待匹配。期望回复为空时不会等待匹配，`超时ms` 会作为重复发送间隔，按重试次数定时重复发送。
- 右键点击指令发送按钮可快速修改指令名称。
- 点击每条指令右侧的 `...` 按钮可编辑指令详情，包括名称、期望回复、期望回复是否 HEX、超时、重试次数和备注。
- 右键点击指令序号可把当前指令移动到指定序号位置。
- 点击“批量”可对当前搜索结果统一设置 HEX/文本类型、超时、重试次数，或删除当前搜索结果；搜索框为空时作用于当前组全部指令。
- 导入指令前会显示导入预览，包含识别到的组和条数；同时会提示空数据、重复名称、HEX 格式异常和疑似高风险指令，确认后追加到当前组或导入对应分组。
- 指令列表中的序号从 1 开始；Lua 的 `serial.send_command_by_index(index)` 使用同样的 1-based 序号。

### Lua 脚本

- 切换脚本下拉框前，当前编辑器内容会自动保存到内置脚本配置中。
- 从文件打开 Lua 脚本后，该脚本路径会记住；之后点击保存或按 `Ctrl+S` 会直接保存到原文件，不会每次弹出另存为窗口。
- 未关联文件路径的新建脚本第一次保存时会弹出保存路径选择框。
- `Tab` 插入 4 个空格；选中多行时 `Tab` 会整体增加缩进，`Shift+Tab` 会整体减少缩进。
- 回车会继承上一行缩进；当行尾是 `then`、`do`、`else`、`function` 或 `repeat` 时会额外缩进一级。
- `Alt+1` 可对当前行或选中多行进行 Lua 注释/取消注释。
- `Ctrl+Shift+Space` 或 `Alt+/` 可弹出代码补全；补全候选列表贴近编辑器光标显示，使用 `Up/Down` 选择，`Enter`、`Tab` 或双击插入，`Esc` 关闭。`Ctrl+Space` 不再绑定，避免和中英文切换冲突。
- 补全项会显示接口签名和参数说明；点击 Lua 工具栏的 API 图标可打开 Lua API 速查，支持分类筛选、最近使用、关键字搜索高亮和插入完整示例。
- 多串口标签页场景下，`serial.send_to("标签名或COM口", data, hex_mode)` 和 `serial.send_hex_to("标签名或COM口", hex)` 可指定目标串口标签发送；`serial.read()`、`serial.wait_for()` 和接收回调仍使用当前运行脚本时选中的串口接收队列。
- API 速查包含 `scenario` 场景示例，例如查询设备、文本等待、回调解析、文件分包发送、协议校验发送和高频发送日志折叠。
- 运行 Lua 前会扫描文件访问、批量发送、OTA/固件升级、关闭日志等风险接口；检测到风险时会弹窗确认，弹框中勾选“不再提示”后后续运行不再弹出，可在设置页重新开启。
- Lua 页面点击“日志”按钮可弹出 Lua 运行日志窗口；该窗口只显示 Lua 脚本运行日志，不替代主收发日志。
- Lua 运行监控会显示当前运行行号；Lua 日志会带 `[L行号]`，行号由 Lua 调用点直接获取；在主日志右键菜单中选择“跳转到Lua脚本行”可定位并高亮脚本行。
- Lua 日志窗口中双击某条 Lua 日志，会跳转并高亮主日志中的对应 Lua 日志条目；关闭串口时，绑定该串口正在运行的 Lua 脚本会同步停止。
- Lua 运行时当前行会在编辑器内高亮；出错行会使用错误高亮。
- Lua 错误详情默认折叠，可点击 Lua 工具栏“错误详情”查看；错误详情会追加错误行附近代码预览，便于直接定位上下文。
- Lua 脚本页状态行可设置日志最低等级和每秒最大 Lua log 条数，并独立显示运行监控信息；超过限制后会折叠为 `Lua日志过多，已折叠 N 条`。
- Lua `serial.on_receive()` 回调支持按设置页参数进行短时间批量合并，避免高频 RX 时每个底层读包都跨线程调用 Lua。
- Lua 页的“导出报告”可把最近一次运行报告、错误详情、当前行号和日志折叠统计导出为 TXT 或 JSON。
- Lua 页的“模板库”包含内置常用模板，也可把当前脚本保存为用户模板，后续双击/插入复用。
- Lua 脚本运行时可以点击运行按钮切换出的停止按钮请求停止；脚本中使用 `serial.sleep(ms)` 时可更快响应停止。
- 使用 `serial.on_receive()` 或 `serial.set_timeout()` 注册回调后，脚本结束前建议调用 `serial.clear_callbacks()` 清理回调。
- 脚本结束、报错或进入监听状态后会输出 `[Lua报告]`，用于快速确认耗时、TX/RX 增量、Lua 日志数、错误数、风险接口数和 Lua API 参数校验提示数。

### AI 助手

- AI 助手位于右侧标签页，界面采用聊天窗口形式：上方为输出区，下方为输入区。
- 在输入区直接输入问题或粘贴日志，按 `Enter` 发送，`Shift+Enter` 换行；工具会自动带当前串口最近 1MB 日志、串口环境、Lua 错误、协议知识片段和已确认经验。
- 如果输入内容本身包含日志或协议数据，会优先分析输入内容，避免和当前日志重复发送。
- 点击“发送”会优先使用设置页配置的远程 AI，并默认使用协议日志分析 Agent 提示词；未配置或调用失败时，会在同一轮回复中显示失败原因并自动切换到本地规则分析。
- 点击“停止”会取消当前请求结果写入；后台请求无法强制终止时，返回结果会被忽略。
- “更多”菜单包含导入协议文档、知识库、学习记录、历史、清空会话、复制输出、插入 Lua、载入解析、保存模板、生成过滤、跳转日志和生成流程等动作。
- “导入协议文档”支持 `.txt`、`.md`、`.csv`、`.json`、`.html`、`.docx`、`.xlsx` 和 `.xls`；工具会在本地保存原始文档并建立轻量关键词索引，远程 AI 只接收命中的协议片段，不直接上传整份协议文档。
- “知识库”可查看已导入的协议知识库；远程分析会自动从全部知识库中匹配最相关的协议片段。
- “学习记录”用于管理 AI 分析后自动生成的候选经验。候选经验需要用户确认后才会参与后续分析；可在确认时修正，也可丢弃或删除。
- “本地分析”不需要网络和 API Key，会按 TX/RX 数量、Lua 日志、超时、重试、CRC/校验、重复 RX、OTA 关键字等规则生成排查建议。
- “生成Lua草稿”会根据上下文中提取到的首条 HEX 数据生成 `serial.send_hex()` + `serial.read()` 示例脚本，插入 Lua 编辑器前仍需用户确认协议和风险。
- “推测协议模板”会从上下文 HEX 数据推测基础协议模板，可复制到“小工具/协议解析”中继续调整字段。
- “远程AI”使用设置页中配置的 OpenAI 兼容接口地址、模型、API Key 和超时时间；默认不脱敏，用户需要自行确认发送内容是否适合交给远程服务。
- 远程 AI 发送前不再弹出确认窗口；默认不脱敏，用户需要自行确认输入内容和当前日志是否适合发送给远程服务。
- AI 任务执行过程中会使用任务令牌避免旧请求覆盖新结果。
- 兼容 OpenAI SSE 的服务会边生成边显示内容；不支持流式的服务会自动按普通 JSON 响应显示。
- AI 会话历史复用 `ai_history.json` 保存，默认每次启动新会话，可在“更多 / 历史”中手动载入旧会话或删除历史。
- 输出区右键支持复制、插入 Lua 编辑器、载入协议解析、生成过滤和跳转日志；这些操作只搬运文本，不会自动执行脚本或发送串口数据。
- AI 结果中如果包含 `行号 | 日志内容`、`日志行: N` 或 `[HH:MM:SS.mmm]`，可双击结果行或点击“跳转日志”尝试定位主日志上下文；也可点击“生成过滤”把当前选中文本作为过滤条件。
- AI 本地和远程分析默认按“问题现象、证据日志、可能原因、建议操作、风险提醒”组织结果；结果区还可将选中内容加入书签、发送到协议解析或生成流程步骤。
- 点击“插入Lua”时，如果 AI 生成的 Lua 代码包含串口发送、循环/批量发送、文件访问或 OTA/写 Flash 关键操作，会再次弹窗确认；该操作只插入编辑器，不会自动运行脚本。
- AI 助手不会自动调用串口发送、执行 Lua 或 OTA。涉及设备写入、批量发送、升级等操作时，应由用户确认后再手动执行。

### 流程编排和小工具

- 流程编排页的“示例”可双击示例名称插入，也可以选中后点击“插入示例”。
- 流程编排页可点击“保存模板”把当前流程保存到本地 `flow_templates.json`，保存后的模板会合并显示在“示例”窗口中。
- 流程编排页顶部操作、参数和状态分行显示；流程编辑区提供横向和纵向滚动条，长流程行不会被右侧面板裁掉。
- 流程编排页提供“步骤表”，可用表格方式填写动作、参数、超时和说明，再生成 `SEND`/`WAIT`/`SLEEP`/`LOG` 文本步骤；点击步骤表空白区域或“取消选中”后，下一次填写会新增步骤而不是更新原步骤。
- 流程参数栏中的参数可用空格、英文逗号或分号分隔，步骤中通过 `${name}` 引用。
- 小工具内每个工具页采用纵向自适应布局，输入区、结果区和操作按钮默认上下排列；右侧面板较窄时不依赖横向滑块，可通过纵向滚动查看完整内容。
- 小工具的 ASCII 页支持在任意输入框输入后自动转换，通常不需要再点转换按钮。
- ASCII 页每一行会带进制提示，二进制、八进制、十进制和十六进制输入均可用空格分隔多项。
- 小工具中的协议解析模板可点击“保存模板”覆盖当前模板，也可以点击“另存模板”输入新名称保存到本地 `protocol_templates.json`；模板支持分类、版本和备注，下次打开会继续保留，并支持导入/导出单个模板或绑定到当前串口。
- 协议解析页的 `CRC校验`、`CRC起始`、`CRC结束` 在同一行显示，起始和结束输入框支持数字、负数、`before:字段`、`after:字段` 和 `$字段` 公式。
- 协议解析页提供“字段表”入口，可用表格编辑字段名、偏移、长度、类型、大小端和显示格式，并自动回写 `field=` 配置；字段类型和大小端使用下拉框选择，减少手动输入错误。字段表支持多选复制/粘贴行、启用/禁用字段和批量调整偏移，并在空表或已选中状态下显示操作提示。
- 协议解析页提供“生成Lua”按钮，可按当前字段表生成 Lua 解析示例并复制到剪贴板，方便粘贴到 Lua 脚本中继续调整。

## 打包

推荐使用 `tools/release/build_release.py` 自动打包并整理发布目录：

```bash
python tools/release/build_release.py
```

该脚本会先运行回归测试、`tools/diagnostics/stability_smoke.py` 稳定性模拟和 `tools/diagnostics/pyside_smoke.py` 当前 PySide UI 冒烟测试，再生成 `release/` 目录，包含单文件 `clcom.exe`、外置 `scripts/`、README、LICENSE、常用配置文件和 `version.json`，不会复制 `examples/`。
如确实需要跳过当前 PySide 冒烟，可加 `--skip-pyside-smoke`，正式发版不建议跳过。需要在发布前追加短时压力测试时，可加 `--pressure-seconds 10`。
如需执行完整发布流水线，可使用：

```bash
python tools/release/release_automation.py
```

该脚本会顺序执行回归测试、稳定性模拟、打包、整理 `release/`、生成 zip、生成 sha256 并更新 `update.json`。默认还会执行 `git push origin master`；如只想本地打包可加 `--no-push`。

如果希望发布前同时生成现场可靠性报告：

```bash
python tools/release/release_automation.py --field-check --pressure-seconds 10
```

该命令会额外调用 `tools/diagnostics/field_reliability_check.py`，报告保存到 `diagnostics/`，用于记录 OTA 高频日志、多串口同时收发、独立窗口隔离、关闭强制落盘、大日志过滤和协议批量解析等发布前检查结果。

如果需要同时创建 Gitee 发行版并上传 zip，可配置 `GITEE_TOKEN` 后执行：

```bash
python tools/release/release_automation.py --field-check --pressure-seconds 10 --publish-gitee
```

正式发布到 Gitee 时默认要求带 `--field-check`，否则脚本会中止，防止跳过现场可靠性检查。确认为紧急发布且已人工完成检查时，可显式追加 `--allow-no-field-check`。

如果需要发布到 GitHub 作为远程更新源，可配置 `GITHUB_TOKEN` 后执行：

```bash
python tools/release/release_automation.py --field-check --pressure-seconds 10 --publish-github
```

GitHub 发布采用最小同步策略：脚本只通过 GitHub API 更新 GitHub 仓库根目录的 `README.md`，不会把其他代码文件上传到 GitHub；随后创建或更新 GitHub Release，并上传 release zip、sha256 和 `update.json`。软件后续检查更新时默认从 GitHub Release 的 `update.json` 查询。

常用参数：
- `--skip-build`：使用已有 `dist/clcom.exe`。
- `--skip-tests`：跳过回归测试和稳定性模拟。
- `--skip-pyside-smoke`：跳过当前 PySide UI 冒烟测试，正式发版不建议使用。
- `--pressure-seconds N`：额外运行 N 秒多串口/日志/协议压力测试。
- `--field-check`：额外运行现场可靠性总检查并生成 Markdown 报告。
- `--allow-no-field-check`：仅用于紧急发布，允许没有 `--field-check` 时创建 Gitee 发行版。
- `--no-push`：不推送代码。
- `--repo owner/repo`：指定 Gitee 仓库，默认 `xianke5200/serial-lua-tool`。
- `--publish-github`：同步 README 到 GitHub，并创建/更新 GitHub Release。

## 发送流程编排

流程编排器支持简单文本步骤，并在界面中提供多个示例：

```text
SEND 1
WAIT 55 AA 1000 HEX
SLEEP 100
LOG done
```

编辑完成后可点击“保存模板”输入模板名称，当前流程会保存到程序目录下的 `flow_templates.json`。保存后的模板会和内置示例一起显示在“示例”窗口中，双击即可重新插入。

- `SEND 1`：发送当前指令组第 1 条指令。
- `SENDHEX AA 55 01`：发送 HEX 数据。
- `SENDTEXT hello`：发送文本。
- `WAIT 55 AA 1000 HEX`：等待 HEX 回复，超时 1000ms。
- `WAITHEX 55 AA 1000`：等待 HEX 回复，等价于上面的 HEX 写法。
- `WAIT OK 1000 TEXT`：等待文本回复 `OK`，适合非 16 进制数据。
- `WAITTEXT VERSION 2000`：等待文本关键字 `VERSION`，超时 2000ms。
- `SET name value`：设置流程变量，后续使用 `${name}` 引用。
- `IF 条件 THEN 步骤`：条件成立时执行单行步骤，支持 `==`、`!=`、`CONTAINS`、`STARTSWITH`、`ENDSWITH`。
- `SLEEP 100`：延时 100ms。
- `LOG text`：输出流程日志。

等待数据不是 16 进制时，推荐显式写 `TEXT` 或使用 `WAITTEXT`：

```text
SENDTEXT AT
WAIT OK 1000 TEXT
LOG 收到OK
```

参数栏可填写流程参数，例如：

```text
addr=01 timeout=1000
```

参数之间可以用空格、英文逗号或分号分隔。

脚本中可以直接引用：

```text
SENDHEX ${addr} 03 00 00 00 01
WAITHEX ${addr} 03 ${timeout}
```

`WAIT`/`WAITHEX`/`WAITTEXT` 匹配成功后会自动生成：

- `${last_reply_hex}`：最后一次等待收到的数据，按 HEX 字符串保存。
- `${last_reply_text}`：最后一次等待收到的数据，按当前编码转文本并去掉首尾空白。

条件判断示例：

```text
SENDTEXT status?
WAITTEXT OK 1000
IF ${last_reply_text} CONTAINS OK THEN LOG 设备状态正常
```

## 日志策略

- UI 收发日志和文件日志记录 RX、TX、Lua 输出和系统信息。
- 日志时间以实际接收时间和实际发送完成时间为准。
- 文件日志按事件时间排序写入。
- 软件关闭或串口关闭前会强制写出队列和排序缓冲区中的剩余日志。
- UI 日志显示区采用虚拟窗口，只渲染当前可见附近的日志切片；结构化事件最多保留最近 100000 条，文件日志不裁剪。
- 主界面的“暂停显示”按钮可临时停止刷新主日志界面，暂停期间日志仍会进入结构化事件和文件日志；暂停后按钮变为“恢复显示”，点击后重绘最近保留的日志。
- 过滤类型、多个关键字和“应用”按钮位于“打开日志/导入日志/清空”同一行，减少收发日志上方工具条占用。
- “解析选中”和“暂停显示”位于收发日志上方工具条右侧，便于直接操作主日志。
- 日志过滤不会替换主日志内容，而是在独立弹窗中列出匹配项；双击匹配项会跳转并高亮主日志中的对应行。
- 日志过滤结果支持复制选中、复制全部和导出到文本文件。
- 日志过滤结果支持“导出上下文”，可把每条匹配日志前后若干条内存日志一起导出，方便查看异常前后收发过程。
- 日志过滤结果可导出为 `txt`、`csv` 或 `jsonl`；`jsonl` 适合后续脚本做自动分析。
- 设置页开启“导出日志时脱敏”后，导出的日志会替换常见 MAC、SN 和本地文件路径。
- 日志过滤支持多个关键字任意匹配，关键字可用英文逗号、分号、中文逗号或中文分号分隔；空格会作为关键字内容参与匹配，只要任意一个关键字匹配就会出现在结果中。
- 日志过滤采用后台线程异步检索，超大日志过滤时不会阻塞主界面操作。
- 过滤结果中选中包含 HEX 字节的 RX/TX 行后，可点击“发送解析”直接载入协议解析页。
- 如果目标日志已被 UI 显示区裁剪，过滤结果仍可查看匹配文本，但上下文需要通过日志文件查看。
- 主日志中选中包含 HEX 字节的 RX/TX 行后，可点击“解析选中”直接载入小工具的协议解析页。
- 主日志表格视图显示当前可见结构化日志，适合按时间、类型、来源、等级和长度快速浏览；右键可复制、解析，双击可跳回文本上下文。
- 点击“索引”可查看当前日志文件旁的 `.idx` 分块索引，并按行号定位最近索引块。
- 日志索引支持按行号和按时间定位最近索引块，可用于大日志快速定位；没有当前索引时可在索引窗口选择历史日志文件，工具会自动查找同名 `.idx`。
- 日志索引窗口定位上下文后可点击“发送AI”，把当前行号/时间附近的日志片段送入 AI 助手，也可切换打开其他历史日志。

## 协议解析模板

小工具中的协议解析支持编辑模板配置和样例数据，当前支持字段：

```text
header=AA55
len_index=2
length_size=1
length_adjust=0
cmd_index=3
crc=none
field=帧头,0,2,hex
field=长度,2,1,uint
field=命令,3,1,uint,big,hex
field=数据,4,2,hex
```

- `header`：帧头，留空表示不检查；批量“按帧头/长度”解析时，如果未填写 `header`，也可通过 `field=帧头,0,2,hex,big,55 55` 或 `field=头,0,2,hex,big,55 55` 这类字段期望值作为分帧帧头；如果字段表没有填写期望值，会根据输入数据中“帧头/头/首个 offset=0 字段”实际解析出的原始字节自动作为后续分帧依据。
- `len_index`：长度字段所在字节下标，支持十进制或 `0x` 十六进制。
- `length_size`：长度字段占用字节数，默认 `1`；批量“按帧头/长度”解析时会使用。
- `length_adjust`：帧总长度修正值，默认 `0`；帧总长度按 `len_index + length_size + 长度字段值 + length_adjust` 计算。
- `cmd_index`：命令字所在字节下标，支持十进制或 `0x` 十六进制。
- `crc`：校验方式，支持 `none`、`modbus`、`crc32`、`xor8`、`sum8`。
- `field`：字段表解析，格式为 `field=名称,偏移,长度,类型[,大小端][,显示格式]`。
- 字段类型支持 `hex`、`uint`、`int`、`ascii`/`text`、`bcd`；大小端支持 `big`、`little`，整数显示格式可写 `hex`。
- 字段偏移和长度支持引用表达式：
  - `after:字段名`：取指定字段结束偏移。
  - `before:字段名`：取指定字段起始偏移。
  - `$字段名`：取前面已解析字段的数值，常用于变长数据长度。
  - `$字段名-1`、`$字段名+2`、`after:命令+$长度`：支持简单公式，允许数字、括号和 `+ - * / %`。
  - `-2`：负数偏移从帧尾倒数计算，常用于最后 2 字节 CRC。
- CRC 配置支持范围表达式，例如 `crc=modbus,0,before:CRC` 表示从第 0 字节计算到 CRC 字段前，并从该位置开始读取 CRC 校验值；CRC 字段可写 `field=CRC,after:数据,2,uint,little,hex` 来指定校验值大小端。
- 协议解析页提供“CRC校验”下拉框，可选 `none`、`modbus`、`crc32`、`xor8`、`sum8`；选择 `none` 时不校验，选择其他模式时使用该模式校验。模板中的 `crc=算法,起始,结束` 仍可保留计算范围，下拉框会覆盖算法类型。
- 协议解析页提供“CRC起始”和“CRC结束”输入框，支持数字、负数、`before:字段`、`after:字段` 和 `$字段` 公式；两者表示参与 CRC 计算的数据区间 `[起始:结束)`，并从 `CRC结束` 位置开始按算法宽度读取原始 CRC 值。例如 CRC32 且帧尾占 2 字节、CRC 位于帧尾前 4 字节时，应填写 `CRC结束=-6`。
- CRC 校验值读取优先使用覆盖该 CRC 字节范围的字段大小端配置，例如 `field=校验值,after:数据,4,hex,little` 会按小端解释校验值；如果未配置匹配字段，则默认按大端读取原始 CRC 字节。
- 协议解析只验证原始帧中的 CRC 是否正确，不会修改或替换输入数据中的原始 CRC 字节。
- 自定义模板保存在程序目录下的 `protocol_templates.json`。
- 模板支持“保存模板”覆盖当前模板，也支持“另存模板”输入新名称保存为独立模板。
- 模板支持导入、导出和绑定当前串口；绑定信息保存在 `protocol_bindings.json`。
- 模板支持分类筛选和分类编辑；解析结果会按字段 offset/length 高亮原始 HEX 字节范围。
- 解析模式支持“单帧、按行、按帧头/长度、固定长度”。
- “按行”会优先把每个非空输入行作为输入块；如果某一行内包含多条同帧头数据，也会继续按帧头和字段表推导长度拆成多帧。“按帧头/长度”会优先根据模板中的 `header`、`len_index`、`length_size` 和 `length_adjust` 自动拆帧；如果没有 `len_index`，会尝试根据字段表中每个字段的 offset/length 公式推导帧总长；“固定长度”会按输入的每帧字节数切分，尾部不足一帧的数据会显示为未解析尾部。
- 批量解析结果会按“第 N 帧”分段输出；字段高亮仅在单帧解析时显示，避免多帧偏移混淆。
- 内置“批量帧示例”模板可直接演示多行帧解析，适合新用户先确认拆帧规则和字段 offset 的关系。
- 内置“字段引用示例”模板可演示通过字段名自动计算数据长度和 CRC 偏移。

## 现场可靠性测试

建议每次发布前至少执行一次真实硬件专项测试：

- OTA 高频日志：连续运行 OTA/字库下载脚本，确认 RX/TX/Lua 日志在界面和文件中无缺失，关闭软件后剩余日志全部落盘。
- 串口拔插恢复：打开串口后拔出再插入，确认状态栏、诊断页、重连次数和最后异常准确，重连成功后可继续收发。
- 长时间运行：保持串口接收和 Lua 监听 2 小时以上，确认 UI 可操作、日志文件持续增长、内存没有异常增长。
- 超大日志：导入或生成十万级日志，确认主日志滚动、过滤弹窗、索引按行号/时间跳转和发送 AI 上下文可用。
- 异常退出：运行脚本并产生日志时关闭窗口，确认日志文件末尾包含关闭提示且最后一批 RX/Lua 日志没有丢失。

## 性能策略

- RX 日志、Lua 日志和 Lua UI 消息采用分批限时刷新，避免高吞吐脚本持续占用 UI 主线程。
- 串口打开、关闭、收发、端口枚举和运行中参数更新集中在 `serial_manager.py`，UI 层只负责状态编排和界面响应。
- 日志事件、异步过滤匹配、文件日志队列和按事件时间排序写入集中在 `log_manager.py`；PySide 会话中的日志落盘、RX 聚合入队、队列 flush、索引写入和关闭强制落盘位于 `clcom/pyside_app/serial/session/log_pipeline.py`。
- 日志文件旁会生成 `.idx` 索引文件，每 1000 行记录一次偏移，后续可用于大日志按行号/时间快速定位。
- 指令列表的格式兼容、搜索匹配、加载和保存集中在 `command_manager.py`。
- 主窗口左右布局、串口标签、右侧功能页和关闭收尾位于 `clcom/pyside_app/main/`；指令列表页面和虚拟模型位于 `clcom/pyside_app/command/`，旧 `serial_gui.py` 和 Tk UI 文件已删除。
- 日志表格视图、表格右键、跳转、异步过滤、过滤模板、历史日志导入、日志显示清空和过滤弹窗位于 `clcom/pyside_app/serial/session/log_view.py`，文件日志管线位于 `log_pipeline.py`，多串口独立窗口按会话隔离状态。
- 串口标签页创建、恢复、配置保存、激活切换、状态同步、拖出独立窗口和双击还原位于 `clcom/pyside_app/main/serial_tabs_controller.py` 与 `clcom/pyside_app/serial/serial_session.py`。
- 串口端口刷新、开关串口、确保打开、端口切换、断线标记、自动重连、手动发送和 Lua 串口发送桥接位于 `clcom/pyside_app/serial/session/serial_io.py` 与 `clcom/core/serial_manager.py`。
- 串口标签页标题、状态标记、端口/名称查找、标签配置快照和恢复等纯逻辑已拆入 `serial_session_logic.py`，减少多串口页面事件处理对主窗口类的直接依赖。
- 串口底部状态栏、诊断报告和压力测试共用 `clcom/core/serial_status.py` 生成会话状态快照；旧 `serial_status_controller.py` 已删除，避免继续保留 Tk 状态刷新包装。
- 配置加载/保存、默认配置、恢复策略、表格列宽收集/恢复和运行中串口参数应用由 `clcom/pyside_app/settings/settings_store.py`、`settings_page.py` 和主窗口状态模块协同处理。
- 当前 PySide 启动状态由 `clcom/pyside_app/main/main_window.py` 和 `main_window_state.py` 承接，旧 Tk 启动初始化和 controller 兼容层已删除。
- PySide Lua 页已拆为 `lua_page.py` 主页面、`lua_script_page.py` 脚本列表/文件保存、`lua_template_page.py` 模板库、`lua_api_page.py` API 速查/补全、`lua_runtime_page.py` 运行/日志/报告和 `lua_editor.py` 编辑器高亮/缩进/快捷键。
- PySide 流程编排页使用 `flow_logic.py` 承载步骤转换、条件判断、单行执行、内置示例和模板读写，`flow_page.py` 保留页面布局、运行线程和串口发送/等待事件。
- 右侧两级标签布局元数据已拆入 `clcom/core/right_tabs.py`，集中维护 `指令/自动/调试/工具` 分组、旧标签名兼容和静态 UI 冒烟检查；当前右侧标签页创建和切换由 PySide 主窗口承接，旧 Tk `right_tabs_controller.py` 已删除。
- 日志视图列定义、过滤结果列定义、过滤查询解析、关键字命中判断、RX 文本/HEX 显示格式化和 UI 降频判断已拆入 `log_view_logic.py`，主窗口只负责渲染和调度。
- 主日志工具栏的显示模式、过滤类型和空状态提示已拆入 `log_toolbar_logic.py`，避免过滤入口继续散落在主界面。
- 设置页分类导航已拆入 `settings_page_logic.py`，避免设置项增减时散落修改跳转位置；设置表单、滚动布局和应用到串口逻辑位于 PySide 设置页。
- 现场可靠性诊断的纯逻辑已拆入 `reliability_checks.py`，串口诊断页和回归测试复用同一套状态判断；串口状态快照和底部统计文案集中在 `clcom/core/serial_status.py`。
- 关于页、工具说明、免责声明、日志目录入口和更新检查由 `clcom/pyside_app/about/about_page.py` 承接；远程更新的版本比较、清单解析和 SHA256 校验集中在 `clcom/services/update_checker.py`，旧 Tk `about_page_controller.py` 和 `update_controller.py` 已删除。
- AI 助手的本地规则分析、整份日志摘要扫描和协议模板推测集中在 `ai_assistant.py`；协议文档知识库、关键词检索、Agent prompt 和学习记录位于 `protocol_agent.py`；AI 页面、历史记录和分析动作位于 `clcom/pyside_app/ai/`。
- 发送队列列定义、过滤项和失败原因分类集中在 `tx_queue_manager.py`，发送记录 UI 只负责显示和右键动作。
- 协议解析配置读取、字段解析、校验和批量拆帧逻辑已拆入 `protocol_parser_logic.py`；协议模板和字段表辅助逻辑位于 `protocol_template_logic.py`，协议解析页面位于 `clcom/pyside_app/tools/protocol_tool_page.py`，旧 Tk `protocol_tool_controller.py` 已删除。
- PySide 小工具采用 `tool_page.py` 注册页面顺序，ASCII、CRC、时间戳、随机数和 Modbus 位于 `simple_tool_pages.py`，协议解析位于 `protocol_tool_page.py`；旧 Tk `tool_panels.py` 已删除。
- 指令列表采用虚拟渲染，只创建当前可见行和少量缓冲行，减少大量指令时的控件数量和闪烁；指令加载/保存、指令组、搜索、收藏、最近发送、导入导出和详情编辑位于 `clcom/pyside_app/command/` 与 `command_manager.py`。
- 主日志显示采用虚拟窗口和缓冲队列，日志事件和文件日志仍实时记录，Text 控件只渲染当前可见切片，减少大量日志刷新时的界面卡顿。
- 文件日志写入采用队列和排序缓冲批量落盘，避免每条 UI 日志都触发同步写文件。
- 导入历史日志时，结构化事件保留最近记录，主界面只渲染最近可显示行，避免超大日志一次性插入导致卡顿。
- 极端刷屏时会限制 UI 待显示缓冲长度；被跳过的只是主界面即时显示，文件日志和过滤事件仍继续保留。
- 窗口拖拽和布局变化做防抖处理，拖拽过程中降低刷新频率，减少边框拖动时的卡顿。
- 源码模块已逐步改为 `clcom.core.*`、`clcom.pyside_app.*`、`clcom.tools.*` 和 `clcom.services.*` 标准包导入，减少旧式平铺导入对目录位置的依赖。
